# BCH Cheat Sheet Generator

Reads a project's mechanical specifications and produces a cheat sheet per trade —
plumbing, sheet metal, hydronic piping — plus a discrepancy log for each. Written
for estimators: what governs quantity, material and scope leads.

Upload whatever the office sent. A whole project manual, one division, a folder
of individual sections, or a mix. Nothing needs renaming or splitting first: the
tool reads the section number off each page and works out what it has.

**If you are picking this project up, read [HANDOVER.md](HANDOVER.md) first.** It
covers how it works and why, what it costs, what is known to be imperfect, and
which oddities are deliberate.

---

## Running it locally

Node.js 20 or newer, and Chrome or Edge installed (PDF rendering drives a real
browser).

```bash
npm install
cp .env.local.example .env.local     # then put your API key in it
npm run dev
```

Open <http://localhost:3000>.

`.env.local` needs one line to run locally:

```
ANTHROPIC_API_KEY=sk-ant-...
```

A deployed server needs a second line stating how access is controlled — see
[HANDOVER.md](HANDOVER.md#running-it). Without it the app refuses to serve any
non-local host, so an unfinished setup cannot end up open on the network.

## Deployment

It runs on a VM inside the BCH network, not a cloud host. A single run takes 15
to 45 minutes, which exceeds the request limits of the hosting services that were
considered, and keeping it in-house means confidential bid documents never leave
the network.

Deployment, the service unit, and the configuration are all in
[HANDOVER.md](HANDOVER.md).

## Commands worth knowing

```bash
npm run split -- <file.pdf>      # what sections are in a book? free, seconds
npm run build:sheets -- <dir>    # scan only: what is in an upload, a few cents
npm run build:sheets -- <dir> --build out/x --trades plumbing
npm run measure -- <sheet.pdf>   # page fill; flags a page under ~90%
npm run check:fonts              # does every character resolve to a webfont?
npm run check:layout             # are the page-break rules still intact?
npm run typecheck
```

`npm run split` is the one to reach for first when a new office's specification
book arrives. It costs nothing, takes seconds, and says whether the format is
understood before anyone spends money on a build.

`PROJECT_NAME` must be set for anything that builds. The scripts refuse to run
without it rather than banner the wrong job.

## How it reads a specification

Each spec section is read on its own, one call per section, and the sheets are
composed from those readings. A single pass over a whole division skims whatever
sits at the edges — on one real Division 23 book a 48,000-character testing and
balancing section was never used at all, and the sheet headed CHEMICAL TREATMENT
did not cite the chemical treatment spec.

Readings are built once per book and reused by every sheet that needs them, which
is what makes reading a whole division for two trades affordable and why two
sheets from one upload agree with each other.

Measured against the earlier single-pass version on the same books: 31
discrepancies against 20 on piping, 38 against 28 on sheet metal, both in fewer
pages.

The reasoning behind the parts that look arbitrary — why the sheet outline is
fixed, why only Divisions 22 and 23 are read in full, why there is no spend cap —
is in [HANDOVER.md](HANDOVER.md).

## What it is not

- **Not a contract document.** It does not replace, amend or govern the
  specification or the drawings.
- **Not a drawings reader.** Specifications only. Anything carried on a drawing or
  a schedule is reported as missing rather than guessed at.
- **Not infallible.** Values are generated by reading the uploaded text and can be
  wrong, stale or incomplete. The discrepancy log is what makes that checkable —
  read it before anyone prices or builds from a sheet.
